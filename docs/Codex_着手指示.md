## 認証と権限【最重要・基本仕様書v1.0第12章】

- 基本は社内利用。アカウントと事業者を分離して保存し、テナント間のデータを分離する。
- メールアドレス＋パスワードのログイン、新規事業者登録で最初のユーザーがオーナー、メール招待から既存／新規ユーザーが参加する方式。
- 標準権限は**オーナー／F（全業務編集＋マスター編集）／V（全閲覧）／P（工事のみ金額を含め閲覧）**。例外のゲストは許可された未受注工事について**工事情報・見積・入金支払を閲覧編集**でき、受注後は即アクセス禁止。
- **設定内の業者・単位マスターはオーナーとFが編集可**。事業者情報・税率・決算月・ユーザー管理はオーナー専用。
- オーナーは「権限削除」でユーザーの事業者アクセス権を剥奪。登録済みの工事データや本人アカウントは消さない。
- **全ユーザー同じUI・同じボタンを表示**。権限不足は通知で説明するが、無権限データは取得不可。API・検索・帳票・直接URL・保存時のアクセス権をサーバー側で検証。
- 上記の認証・権限は本番実装の要件。UI試作中に安全性を実装したかのように見せない。

## 最初の実装依頼

1. 既存の `index.html` / `construction.html` / `style.css` / `app.js` は**古いローカルUI試作**。見た目と導線の参考にし、本番の権限・保存実装と混同しない。
2. トップ主タブは**工事／収支**。収支は**収支台帳／支出台帳／入金一覧／支払一覧**の4画面。トップの共通入口は**設定一本**。
3. 最初はトップの構成と移動をPC・スマホで操作確認できるUI試作から始める。未決定の処理を仮実装する場合、仮であることを明記する。
4. 支払額の空欄と`0`は別。**自社人工も支払カードを作成し、支払額0円は手入力**。古い指示と逆なので注意。
5. **受注後は提出側の金額を構成するセルをロック**。**計上後は原価側・取引先もロック**。ただし**支払額の訂正と入金・支払実績日の入力は許可**。
6. 支払額の訂正で予算側を自動書換えしない。入力済み支払データを再集計などで黙って消去しない。
7. 相殺・回収不能・請求訂正は実入出金ではない。収支台帳・支出台帳に転記しない。
8. 税抜実績原価換算、精算調整の取消、部分入金、印影アップロードの保管権限等、未決定をCodexが独断で確定しない。
9. 本番化する場合はサーバー側でテナント・工事別権限制御、認証、競合しない採番、データ保護を実装する。HTMLを公開するだけでは本番にできない。

まず画面構成の差分と小さなUI実装計画を示し、未決定事項を勝手に決めずに進める。
